The Epipolar Constraint

A 3D point P visible in both images projects to \mathbf{p}_1 in image 1 and \mathbf{p}_2 in image 2. Even though we don't know where P is in 3D, we know that \mathbf{p}_2 must lie on a specific line in image 2, the epipolar line of \mathbf{p}_1. The Fundamental Matrix F encodes this constraint for all possible points.

The math

For any true match (\mathbf{p}_1, \mathbf{p}_2), with points in homogeneous coordinates \mathbf{p}_i = (x_i, y_i, 1)^{\mathsf{T}}:

\mathbf{p}_2^{\mathsf{T}}\, F\, \mathbf{p}_1 = 0

F is 3\times 3, rank 2, and carries 7 degrees of freedom: nine entries, minus one for overall scale, minus one for the rank constraint.

\begin{aligned} F\,\mathbf{p}_1 \;&\longrightarrow\; \text{epipolar line in image 2} \\ F^{\mathsf{T}}\mathbf{p}_2 \;&\longrightarrow\; \text{epipolar line in image 1} \end{aligned}

What this enables

For an inlier match (p₁, p₂):
  p₂ᵀ F p₁  ≈  0  (small residual)

For an outlier (wrong match):
  p₂ᵀ F p₁  ≫  0  (large residual)

→ F is the inlier/outlier separator.
  RANSAC uses this to clean up the
  noisy match list from Ch 01.

The 8-Point Algorithm

Expanding \mathbf{p}_2^{\mathsf{T}} F \mathbf{p}_1 = 0 with \mathbf{p}_1 = (u, v, 1) and \mathbf{p}_2 = (u', v', 1) gives a linear equation in the 9 entries of F. Stack N such equations into a matrix system.

The math

Each match contributes one row to A:

\mathbf{a}_i = \begin{bmatrix} u'u & u'v & u' & v'u & v'v & v' & u & v & 1 \end{bmatrix}
A\,\operatorname{vec}(F) = \mathbf{0}, \qquad A \in \mathbb{R}^{N \times 9}

Take the SVD A = U\Sigma V^{\mathsf{T}}; the solution is the last row of V^{\mathsf{T}}. Then force the result back to rank 2 by zeroing its smallest singular value:

F = U \operatorname{diag}(\sigma_1, \sigma_2, 0)\, V^{\mathsf{T}}

Code: eight_point()

A = np.column_stack([
    pts2_n[:,0]*pts1_n[:,0],  # u'u
    pts2_n[:,0]*pts1_n[:,1],  # u'v
    pts2_n[:,0],               # u'
    pts2_n[:,1]*pts1_n[:,0],  # v'u
    pts2_n[:,1]*pts1_n[:,1],  # v'v
    pts2_n[:,1],               # v'
    pts1_n[:,0], pts1_n[:,1], # u, v
    np.ones(len(pts1_n)),      # 1
])
_, _, Vt = np.linalg.svd(A)
F = Vt[-1].reshape(3, 3)     # ← solution

U, S, Vt = np.linalg.svd(F)
S[2] = 0.0                   # ← rank-2
F = U @ np.diag(S) @ Vt

Hartley Normalisation: Why It's Non-Negotiable

Pixel coordinates on our 3024 \times 2016 images reach values up to \sim\!3000. The A matrix contains products like u'u \approx 9 \times 10^{6}. SVD on such a poorly conditioned matrix is dominated by floating-point rounding, so the recovered F is meaningless. Normalisation maps both point sets to zero mean and \sqrt{2} average distance from the origin.

The math

Centre the points on the origin and scale them so their mean distance from it is \sqrt{2}:

\mathbf{c} = \frac{1}{N}\sum_{i=1}^{N} \mathbf{p}_i, \qquad s = \frac{\sqrt{2}}{\frac{1}{N}\sum_{i=1}^{N} \lVert \mathbf{p}_i - \mathbf{c} \rVert}
T = \begin{bmatrix} s & 0 & -s\,c_x \\ 0 & s & -s\,c_y \\ 0 & 0 & 1 \end{bmatrix}, \qquad \tilde{\mathbf{p}} = T\,\mathbf{p}

Estimate \tilde{F} in the normalised frame, then undo the transform:

F = T_2^{\mathsf{T}}\, \tilde{F}\, T_1

Code: normalize_points()

centroid = pts.mean(axis=0)
shifted  = pts - centroid
scale    = np.sqrt(2) / np.mean(
               np.linalg.norm(shifted, axis=1))

T = np.array([
    [scale, 0,    -scale*centroid[0]],
    [0,     scale, -scale*centroid[1]],
    [0,     0,      1               ],
])

pts_h    = np.hstack([pts, np.ones((len(pts),1))])
pts_norm = (T @ pts_h.T).T

# Denormalise after computing F:
F = T2.T @ F @ T1
return F / F[2, 2]   # fix scale (convention)
Challenge I hit Skipping normalisation gives mean reprojection error of ~18 px. With it: ~0.14 px on the best RANSAC sample, ~0.50 px after refitting on all inliers. Normalisation is not an optimisation. It is the difference between the algorithm working and not working.

Symmetric Epipolar Distance (SED)

To count inliers we need a geometric distance between a match and its epipolar line, in pixel units. The algebraic residual \mathbf{p}_2^{\mathsf{T}} F \mathbf{p}_1 is not geometric — its scale is arbitrary. SED sums the point-to-line distances in both images.

The math

The two epipolar lines and the algebraic residual:

\boldsymbol{\ell}_2 = F\,\mathbf{p}_1, \qquad \boldsymbol{\ell}_1 = F^{\mathsf{T}}\mathbf{p}_2, \qquad r = \bigl\lvert \mathbf{p}_2^{\mathsf{T}} F\, \mathbf{p}_1 \bigr\rvert

Dividing by the line normal turns that residual into a real point-to-line distance in pixels:

d_2 = \frac{r}{\lVert (F\mathbf{p}_1)_{xy} \rVert_2}, \qquad d_1 = \frac{r}{\lVert (F^{\mathsf{T}}\mathbf{p}_2)_{xy} \rVert_2}
\mathrm{SED} = d_1 + d_2 \;<\; 1.5\ \text{px}

Code: symmetric_epipolar_distance()

p1h  = np.hstack([pts1, np.ones((len(pts1),1))])
p2h  = np.hstack([pts2, np.ones((len(pts2),1))])
Fp1  = (F   @ p1h.T).T   # lines in image 2
Ftp2 = (F.T @ p2h.T).T   # lines in image 1

# numerator: algebraic residual per match
num    = np.abs((p2h * Fp1).sum(axis=1))

# denominators: line direction norms (xy only)
denom1 = np.sqrt(Fp1 [:,0]**2 + Fp1 [:,1]**2)
denom2 = np.sqrt(Ftp2[:,0]**2 + Ftp2[:,1]**2)

return num/denom1 + num/denom2  # px

RANSAC: Adaptive Iteration Count

Even after the ratio test, ~30–40% of matches are outliers. Feeding them all into eight_point at once gives garbage. RANSAC draws minimal random samples (8 matches), estimates F, counts inliers via SED, and keeps the best.

The math

With w the inlier fraction, estimated online, the chance that all eight sampled points are inliers is:

p_{\text{good}} = w^{8}

so the number of iterations needed for confidence p is

n = \frac{\log(1-p)}{\log\!\left(1-w^{8}\right)}

As RANSAC finds a better F, w rises, n falls, and it can stop early.

Code: estimate_fundamental()

w_est   = 0.5          # initial guess: 50% inliers
n_iters = max(100, int(
    np.log(1 - 0.999) / np.log(1 - w_est**8)))
rng     = np.random.default_rng(0)  # reproducible

for iteration in range(n_iters):
    idx    = rng.choice(n, 8, replace=False)
    F_cand = eight_point(pts1[idx], pts2[idx])
    inlier = sed(F_cand, pts1, pts2) < threshold
    count  = inlier.sum()

    if count > best_count:
        best_count, best_mask, best_F = count, inlier, F_cand
        w_est   = count / n
        n_iters = min(n_iters,
            int(np.log(1-0.999) /
                np.log(1-max(w_est**8, 1e-10)))
            + iteration)

# Final refit on all inliers:
if best_mask.sum() >= 8:
    best_F = eight_point(pts1[best_mask], pts2[best_mask])
Key insight The final eight_point(pts1[best_mask], pts2[best_mask]) refit is crucial. The best RANSAC sample used only 8 points. Refitting on all ~900 inliers gives a much more stable F. This is what drives the final 0.50 px mean reprojection error.

Pitfalls

Normalise F after every eight_point call. The F / F[2,2] convention fixes scale across iterations. Without it, the SED threshold is effectively different each iteration, so inlier counts become incomparable.

Use a fixed random seed during development. np.random.default_rng(0) makes RANSAC deterministic, which you need when debugging why inlier counts fluctuate.

SED only uses the xy components of epipolar line vectors. The third component (the offset term) does not contribute to the geometric distance. Including it in the norm is a subtle but consequential bug. Always index [:, 0] and [:, 1] for the denominator.
